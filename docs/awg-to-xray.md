# 🔁 Перестал работать AmneziaWG — переходите на XRay

Если AWG перестал подключаться или соединение «висит», дело, скорее всего, в сети, а не в протоколе. AWG работает поверх **UDP**, а у части провайдеров UDP-трафик может не работать совсем или ограничиваться — по скорости, по времени сессии или только на отдельных направлениях.

Решение — перевести сервер на **XRay (VLESS + Reality)**: он идёт поверх **TCP + TLS** и для провайдера выглядит как обычное HTTPS-соединение с крупным сайтом.

::: tip Коротко
**Порт** `443` · **SNI** — крупный зарубежный сайт, доступный в РФ (или свой домен) · **Fingerprint** — `firefox`
:::

## Симптомы {#symptoms}

- Подключение бесконечно «крутится» и обрывается по таймауту.
- AWG работал раньше и перестал без изменений в настройках.
- В другой сети (другой оператор, проводной интернет) тот же AWG подключается.

::: warning Сервер не отвечает даже по SSH?
Тогда дело не в протоколе — начните с **[пошаговой диагностики](/vpn-troubleshooting#error-305)**.
:::

## Решение по шагам {#fix}

1. **Обновите приложение.** Скачайте последнюю версию клиента AmneziaVPN с GitHub — это обязательно, в старых версиях XRay работает некорректно.
2. **Решите, оставлять ли AWG.** На тарифе **Start** удалите AWG в настройках сервера внутри приложения: держать два протокола сразу на 1 ГБ памяти [не рекомендуем](/choose-plan). На **Basic** и выше AWG можно оставить — XRay установится рядом, и в приложении можно переключаться между ними.
3. **Установите XRay.** Нажмите **«Добавить протокол»** → **XRay** и укажите параметры маскировки:

| Параметр | Значение | Комментарий |
| --- | --- | --- |
| **Порт** | `443` | стандартный порт HTTPS, другой выглядит подозрительно |
| **SNI** | `www.nvidia.com` или `www.rolex.com` | любой крупный **зарубежный** сайт, доступный в РФ — [подробнее](#sni) |
| **Fingerprint** | `firefox` | вместо `chrome` по умолчанию — [подробнее](#fingerprint) |

::: info Где это в приложении
SNI и Fingerprint находятся в **XRay настройки сервера** → **Security** → **Reality**. Пошагово — в разделе [Смените fingerprint на firefox](#fingerprint).
:::

4. Дождитесь установки (до минуты) и подключитесь, выбрав XRay в списке протоколов.

## Какой SNI выбрать {#sni}

SNI — это домен, под который маскируется ваше соединение. Провайдер видит его в начале TLS-рукопожатия и сопоставляет с IP-адресом, куда реально идёт трафик.

::: danger Не используйте российские сайты
`ya.ru`, `2gis.ru`, `pochta.ru`, `vk.com` и подобные — **плохая маскировка**. Эти сайты живут на российских IP, а ваш сервер — за рубежом. Соединение «с Яндексом» на зарубежный IP хостинга — это явное несоответствие, которое DPI замечает в первую очередь.
:::

Выбирайте домен по трём признакам:

- **Зарубежный и крупный** — международный бренд, у которого естественно много трафика из любых стран.
- **Доступен в РФ** — открывается без VPN. Заблокированный сайт в SNI сразу привлекает внимание.
- **Поддерживает TLS 1.3 и HTTP/2** — без этого Reality не заработает. Как проверить — **[XRay: проверка домена](/xray-tuning#verify)**.

| Вариант | Пример | Маскировка |
| --- | --- | --- |
| 🥇 **Свой домен (Self-SNI)** | `mysite.duckdns.org` | **лучшая** — IP, домен и сертификат совпадают |
| 🥈 Крупный зарубежный сайт | `www.nvidia.com`, `www.rolex.com` | хорошая, подходит большинству |
| ❌ Российский сайт | `ya.ru`, `2gis.ru` | плохая — не используйте |

::: tip Лучший вариант — Self-SNI
С чужим доменом всегда остаётся расхождение: домен указывает на один IP, а трафик идёт на другой. Если поднять на сервере свой домен и сайт-прикрытие, такого расхождения нет вовсе — наблюдатель видит домен, который действительно живёт на этом IP и отдаёт свой сертификат.

Пошаговый гайд с бесплатным доменом: **[🔐 Self-SNI для VLESS + Reality](/self-sni)**.
:::

## Смените fingerprint на firefox {#fingerprint}

Fingerprint (`fp`) определяет, под какой браузер клиент подделывает TLS-рукопожатие. По умолчанию стоит `chrome` — его используют почти все VPN-клиенты, поэтому он стал самым «примелькавшимся» отпечатком. Смените его на **`firefox`**.

**В приложении AmneziaVPN:**

1. Откройте настройки сервера → протокол **XRay** → **XRay настройки сервера**.
2. Перейдите в раздел **Security** — там должно быть выбрано **Reality**.
3. В поле **Fingerprint** выберите **`firefox`**. Здесь же, в поле **Имя сервера (SNI)**, задаётся домен маскировки.
4. Нажмите **Сохранить**.

**В ссылке `vless://`** — параметр `fp=firefox`:

```text
vless://<UUID>@<IP-или-домен>:443?security=reality&sni=www.nvidia.com&fp=firefox&pbk=<PublicKey>&sid=<ShortId>&flow=xtls-rprx-vision&type=tcp#xray
```

Подробнее о смене отпечатка — **[XRay: смена fingerprint](/xray-tuning#fingerprint)**.

## Если не заработало {#fallback}

Меняйте **по одному параметру за раз**, иначе не поймёте, что помогло:

| Что менять | Варианты | Когда пробовать |
| --- | --- | --- |
| **SNI** | другой крупный зарубежный сайт, затем [Self-SNI](/self-sni) | текущий домен не проходит DPI |
| **Fingerprint** | `firefox` → `safari` → `edge` | соединение рвётся на этапе рукопожатия |
| **Порт** | `8443` | только если 443 занят на сервере чем-то другим |
| **Сеть** | другой оператор, проводной интернет | чтобы понять, в чьей сети фильтрация |

::: details Как понять, что 443 занят
Подключитесь к серверу по SSH и выполните:

```bash
ss -tlnp | grep :443
```

Если в выводе есть процесс, отличный от Xray, — порт занят. Освободите его или используйте `8443`.
:::

## AmneziaWG и XRay: в чём разница {#why}

AmneziaWG и XRay не конкурируют, а дополняют друг друга. Оба протокола надёжно маскируют трафик, разница — в транспорте: AWG работает поверх UDP, XRay — поверх TCP. Поэтому каждый лучше всего раскрывается в своих условиях.

| | AmneziaWG | XRay (VLESS + Reality) |
| --- | --- | --- |
| **Транспорт** | UDP | TCP + TLS |
| **Скорость и задержки** | максимальные — лучший выбор для звонков, игр и видео | высокие, с небольшими накладными расходами TCP |
| **Нагрузка на устройство и батарею** | минимальная | немного выше |
| **Маскировка** | собственная обфускация: пакеты не похожи ни на WireGuard, ни на другие известные VPN | соединение выглядит как HTTPS-сессия с сайтом из SNI |
| **Где особенно выручает** | большинство сетей, повседневное использование | сети, где UDP ограничен или не работает |

::: info Почему UDP иногда не проходит
У части провайдеров UDP-трафик может не работать или ограничиваться: урезается скорость, соединения обрываются через несколько минут, или UDP закрыт целиком. Чаще всего это встречается у мобильных операторов, в корпоративных сетях и публичном Wi-Fi. Это особенность конкретной сети, а не протокола — в таких сетях выручает XRay, который работает поверх TCP.
:::

::: tip Держите на сервере оба протокола
AWG — основной протокол на каждый день: он быстрее и экономнее. XRay — запасной для сетей, где режется UDP. Переключение между ними в приложении занимает пару секунд.

Для двух протоколов сразу нужен тариф **Basic** или выше. На **Start** оставьте один — тот, что работает в вашей сети. Тариф меняется за пару минут с сохранением данных и IP — [📦 Изменение тарифа](/change-plan).
:::
